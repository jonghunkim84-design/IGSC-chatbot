# IGSC 인증 문의 챗봇 — 사용자 교육 매뉴얼

이 자료는 **챗봇을 처음 운영하시는 분**을 위한 교육 자료입니다. 컴퓨터 용어나 시스템 지식이 없어도 따라 할 수 있도록, 챗봇이 어떻게 일하는지부터 관리자 화면에서 매일 하는 일까지 **순서대로, 쉬운 말로** 설명합니다.

> 기준일 2026-10-04 · 고객이 보는 챗봇 https://igsc-chatbot.vercel.app/chat · 관리자 화면 https://igsc-chatbot.vercel.app/admin

## 교육 안내

| | |
|---|---|
| 대상 | 관리자 계정을 받는 운영 담당자 (관리자는 최대 3명) |
| 교육 목표 | ① 챗봇이 어떤 규칙으로 답하는지 설명할 수 있다 ② FAQ를 만들고, 확인하고, 승인할 수 있다 ③ 챗봇이 답하지 못한 질문을 처리할 수 있다 ④ 문서(파일)에서 FAQ 초안을 만들고 확인할 수 있다 ⑤ 매일·매주·매달 해야 할 일을 안다 |
| 준비물 | 관리자로 등록된 이메일 주소, 컴퓨터와 인터넷 브라우저(크롬 등). 로그인할 때 받은 메일의 링크는 **로그인을 요청한 같은 브라우저**에서 열어야 합니다. |
| 소요 시간 | 약 2시간 30분 (실습 포함) |

### 진행 순서 (예시)

| 시간 | 내용 | 장 |
|---|---|---|
| 15분 | 챗봇이 무엇이고 어떤 규칙으로 답하는지 | 1장 |
| 10분 | 고객이 보는 챗봇 화면 시연 | 2장 |
| 15분 | 관리자 화면 로그인과 메뉴 | 3장 |
| 60분 | 핵심 업무 따라 하기 (FAQ 만들기, 미답변 처리, 문서로 초안 만들기, 재검토) + 실습 | 4장 |
| 15분 | FAQ를 잘 쓰는 방법과 승인 전 체크리스트 | 5장 |
| 15분 | 운영 루틴과 운영 상태 화면 | 6장 |
| 20분 | 정리, 질의응답, 문제가 생겼을 때 | 7·8장 |

> **교육 중 주의** — 지금은 아직 고객이 승인한 FAQ가 **한 건도 없습니다**(0건). 그래서 챗봇은 어떤 질문에도 답을 하지 못합니다. 교육 중 실습에서 **승인한 FAQ는 실제 운영 챗봇에 바로 나갑니다.** 실습용 FAQ는 질문 앞에 `[실습]`을 붙이고, 실습이 끝나면 꼭 **초안으로 되돌리거나 삭제**해 주세요.

### 처음 보시는 분을 위한 용어 풀이

이 자료에서 계속 나오는 말입니다. 먼저 읽어 두시면 이해가 쉽습니다.

| 용어 | 쉬운 설명 |
|---|---|
| **FAQ** | "자주 묻는 질문"과 미리 정해 둔 "답변"을 한 쌍으로 묶은 것입니다. **챗봇은 FAQ에 있는 내용으로만 답합니다.** |
| **초안 / 승인** | FAQ의 상태입니다. **초안**은 아직 작성·확인 중인 상태로, 고객에게 보이지 않습니다. **승인**은 사람이 확인을 마친 상태로, 이때부터 챗봇이 이 FAQ로 답합니다. |
| **다른 표현** | 같은 질문을 사람마다 다르게 말하는 것을 모아 둔 것입니다. 예) "비건 인증 비용은?" = "비건인증 얼마" = "비건 인증 가격". 챗봇은 이것을 보고 어떤 FAQ가 맞는지 찾습니다. |
| **담당자 이관** | 챗봇이 답하지 않고 "담당자가 확인해 드립니다"라고 안내하며 사람에게 넘기는 것입니다. |
| **미답변 질문** | 챗봇이 답하지 못해 담당자에게 넘긴 질문을 모아 둔 목록입니다. **새 FAQ를 만드는 출발점**입니다. |
| **보완 필요** | 답변을 아직 정하지 못해 **비워 둔 FAQ**입니다(예: 인증별 비용·기간). 이런 FAQ는 승인할 수 없고, 챗봇도 사용하지 않습니다. |
| **문서 보관함** | 인증 안내서·절차서 같은 **파일(PDF, 워드 등)을 올려 두는 곳**입니다. 이 파일에서 FAQ 초안을 자동으로 만들 수 있습니다. |
| **출처** | 답변이 어디에서 나왔는지 알려 주는 홈페이지 주소(링크) 또는 문서입니다. |

## 1. 챗봇이 무엇이고, 어떻게 일하나요?

### 1-1. 한마디로
고객이 홈페이지의 챗봇에게 인증에 대해 물어보면(가능 여부, 비용, 기간, 절차, 필요 서류 등), 챗봇이 **사람이 미리 확인해서 승인한 FAQ의 내용만** 가지고 답합니다. FAQ에 없는 내용이거나 답하면 안 되는 질문이면, **억지로 답하지 않고 담당자에게 연결**합니다.

챗봇이 마음대로 지어내서 답하는 일이 없도록 만든 구조입니다. 인증기관의 답변은 정확해야 하기 때문입니다.

| 구성 | 하는 일 | 쓰는 사람 |
|---|---|---|
| **챗봇 화면** (홈페이지 오른쪽 아래 둥근 버튼) | 고객의 질문에 답합니다. | 고객 |
| **관리자 화면** (`/admin`) | FAQ 만들기·승인, 미답변 질문 처리, 문서 올리기, 대화 기록과 통계 보기 | 운영 담당자 (여러분) |
| **데이터 저장소** | FAQ, 대화 기록, 문서 파일 등을 안전하게 보관합니다. | (시스템이 알아서 관리) |

### 1-2. 챗봇이 반드시 지키는 5가지 규칙
사람이 신경 쓰지 않아도 **시스템이 스스로 지키도록** 만들어져 있습니다.

1. **승인된 FAQ로만 답합니다.** 맞는 FAQ가 없으면 답을 지어내지 않고 담당자에게 연결합니다.
2. **컨설팅은 하지 않습니다.** "어떻게 하면 인증에 통과하나요?" 같은 질문에는 방법을 알려 주지 않습니다. 인증기관이 인증을 받으려는 회사에 방법을 코치해 주면 심사가 공정하지 않게 되기 때문입니다(국제 기준 ISO 17065의 공평성 원칙). 대신 외부 전문 컨설팅 기관에 문의하라고 안내합니다.
3. **비용과 기간은 확정된 값만 알려 줍니다.** 추측해서 말하지 않으며, 항상 "참고용이며 담당자 검토 후 확정됩니다"라는 문구를 붙입니다. 확정값이 없으면 담당자에게 넘깁니다.
4. **"우리 제품도 인증받을 수 있나요?"에는 확답하지 않습니다.** 비슷한 제품의 인증 사례를 참고로 보여 주고, 최종 판단은 담당자가 한다고 안내합니다.
5. **모든 대화를 기록합니다.** 챗봇이 답하지 못한 질문은 관리자에게 모입니다.

### 1-3. 운영의 핵심: 질문이 FAQ가 되는 순환

```
고객이 질문 ─▶ 챗봇이 승인된 FAQ로 답변
   └─ 답하지 못함 ─▶ [미답변 질문]에 쌓임 ─▶ 관리자가 FAQ로 만들고 승인 ─▶ 다음 고객부터는 바로 답변
```

**챗봇이 똑똑해지는 방법은 승인된 FAQ를 늘리고 다듬는 것**입니다. 운영 담당자의 일은 이 순환을 꾸준히 돌리는 것입니다.

### 1-4. 질문 하나가 처리되는 과정
고객이 질문을 보내면, 챗봇은 아래 순서로 **항상 똑같이** 처리합니다.

1. **분류** — 질문이 어떤 종류인지 먼저 구분합니다: ① 인증에 대한 정보 문의 ② 컨설팅 요청 ③ 불만·이의제기 ④ 인증과 관계없는 질문
2. **갈림길** — ②③④는 여기서 끝납니다. 미리 정해 둔 안내 문구만 나가고, AI가 새로 답을 만들지 않습니다.
3. **FAQ 고르기** — ①번이면 승인된 FAQ 중에서 질문과 관련된 것을 최대 5개 고릅니다. 모든 인증에 해당하는 **공통 FAQ**(절차, 서류 등)도 함께 살펴봅니다.
4. **답변 쓰기** — 고른 FAQ의 내용만으로 답변을 씁니다. 출처 링크나 안내 문구는 자동으로 붙습니다.
5. **기록** — 질문, 답변, 근거로 쓴 FAQ를 대화 기록에 남깁니다.

### 1-5. 처리 결과 7가지와 운영자가 할 일
대시보드와 대화 기록에는 질문이 어떻게 처리됐는지 아래처럼 표시됩니다.

| 처리 결과 | 어떤 경우인가요? | 고객에게 나가는 것 | 운영자가 할 일 |
|---|---|---|---|
| **답변 완료** | 승인된 FAQ로 답했습니다. | 답변 + 출처 링크 | 가끔 답이 정확한지 확인 |
| **부분 안내** | 질문 중 **일부만** FAQ로 답할 수 있었습니다. | FAQ로 답할 수 있는 부분까지 답하고, 나머지는 "담당자가 확인해 드립니다" | **미답변 질문**에서 빠진 부분을 FAQ로 추가 |
| **담당자 이관** | 맞는 FAQ가 없거나, '보완 필요' FAQ이거나, 시스템 오류이거나, 외국어 질문입니다. | "담당자 확인이 필요합니다" + 연락처 | **미답변 질문**에서 FAQ로 만들기 (가장 중요한 일) |
| **인증 종류 되묻기** | 어떤 인증인지 알 수 없는 질문입니다(예: "얼마나 걸려요?"). | "어떤 인증에 대한 문의이신가요?" + 선택 버튼 | 없음 (고객이 버튼을 누르면 이어집니다) |
| **컨설팅 차단** | 통과하는 방법, 기준 맞추는 법 등을 물었습니다. | 공평성 안내 + 외부 컨설팅 안내 | 없음. 이런 질문에 답하는 FAQ는 **만들지 마세요** |
| **불만 접수** | 불만, 이의제기, 항의입니다. | 접수 방법 + 연락처 | **담당자가 직접 대응** |
| **범위 밖** | 인증과 관계없는 질문입니다(날씨, 잡담 등). | "인증 문의 전용 챗봇입니다" 안내 | 없음 |

### 1-6. 시스템이 알아서 붙여 주는 문구 (FAQ 답변에 직접 쓰지 않아도 됩니다)

| 자동으로 붙는 것 | 언제 붙나요? |
|---|---|
| 출처 링크 | FAQ에 출처 주소가 적혀 있을 때 |
| "비용·기간은 참고용이며 담당자 검토 후 확정됩니다" | 비용·기간 FAQ로 답할 때 |
| "인증 가능 여부는 담당자가 검토한 뒤 확정됩니다" | 제품의 인증 가능 여부를 물었을 때 |
| 비슷한 제품의 인증 사례 | 가능 여부를 물었고, 공개에 동의한 사례가 있을 때 |

### 1-7. '초안'과 '승인' — 가장 중요한 개념

- **승인된 FAQ만** 챗봇이 사용합니다. **초안은 고객에게 절대 보이지 않습니다.** 마음 놓고 작성하고 고칠 수 있는 작업 공간이라고 생각하세요.
- **승인은 사람이 직접 버튼을 눌러야만** 됩니다. 문서에서 자동으로 만들어진 초안도 예외가 없습니다.
- 저장하면 챗봇 답변에 **바로** 반영됩니다. 기다리거나 따로 배포할 필요가 없습니다.
- 누가 언제 승인했는지 **승인한 사람의 이메일과 시각이 기록**됩니다(FAQ 목록의 '승인자' 칸).
- **'보완 필요'(담당자 입력 필요)** 표시가 있는 FAQ는 답변이 아직 정해지지 않은 것입니다. 답변을 채우고 표시를 해제해야 승인할 수 있습니다.

## 2. 고객이 보는 챗봇 화면

### 2-1. 사용 방법
1. 홈페이지 **오른쪽 아래의 동그란 버튼**을 누릅니다. (PC에서는 작은 대화창이, 스마트폰에서는 전체 화면이 열립니다.)
2. 화면에 보이는 **추천 질문 버튼**(인증 비용, 소요 기간, 인증 절차, 인증 종류 안내)을 누르거나, 아래 입력창에 질문을 쓰고 **전송**을 누릅니다.
3. 대화창을 닫았다가 다시 열면 대화가 남아 있고, 페이지를 새로고침하면 처음부터 다시 시작합니다.

### 2-2. 이렇게 물어보면 더 잘 답합니다

| 좋은 질문 | 아쉬운 질문 |
|---|---|
| 비건 인증 비용이 얼마인가요? | 얼마예요? |
| 식품 비건 인증은 어떤 원칙으로 심사하나요? | 심사는 어떻게 해요? |

- **인증 이름을 함께 쓰면** 가장 정확합니다.
- 한 번에 **하나의 질문**만, **500자 이내, 한국어**로 써 주세요.
- 인증 이름이 없으면 챗봇이 "어떤 인증에 대한 문의이신가요?"라고 되묻습니다. 아래 **인증 종류 버튼**을 누르면 이어서 답합니다.
- 답변 아래의 **출처 ↗**는 답의 근거가 된 공식 페이지이고, **상담 신청 ↗**은 IGSC 상담 페이지가 새 창으로 열리는 버튼입니다.
- 고객에게는 연락처 같은 **개인정보는 입력하지 말라고** 안내하고 있습니다. 질문과 답변은 서비스 개선을 위해 기록됩니다.
- 같은 사람이 **짧은 시간에 질문을 너무 많이** 보내면 "잠시 후 다시 시도해 주세요"가 나옵니다. 사용량과 AI 비용이 갑자기 늘어나는 것을 막기 위한 장치로, 한 사람당 1분에 15번, 1시간에 120번까지 가능합니다. 일반적인 사용에서는 걸리지 않습니다.

### 2-3. 강사용 시연 순서
교육에서 아래 5가지를 직접 입력해 보면 챗봇의 성격이 한눈에 보입니다.

1. 비용을 묻는다 → 안내 문구가 붙는 것을 확인
2. "어떻게 하면 통과하나요?" → 정중한 거절
3. "얼마나 걸려요?" → 어떤 인증인지 되묻기
4. 인증과 관계없는 질문 → "인증 문의 전용" 안내
5. 불만을 말한다 → 담당자 연결 안내

## 3. 관리자 화면 시작하기

### 3-1. 로그인 (비밀번호가 없는 방식입니다)
1. 인터넷 브라우저에서 `/admin` 주소로 들어가 **등록된 이메일 주소**를 입력하고 **로그인 링크 받기**를 누릅니다.
2. 받은 메일을 열어 안의 **링크를 클릭**합니다. 반드시 **로그인을 요청한 같은 브라우저**에서 열어야 합니다.
3. 등록되지 않은 이메일은 메일이 오지 않습니다(화면에는 똑같은 안내가 나옵니다). 메일이 안 오면 **스팸함**도 확인해 보세요.
4. 보안을 위해 로그인 요청을 짧은 시간에 반복하면 잠시 막힙니다(1시간에 5번까지).

### 3-2. 화면 위쪽 메뉴

## 4. 핵심 업무 따라 하기

### 4-1. FAQ 새로 만들기
1. 위쪽 메뉴 **FAQ** → 오른쪽 위의 **+ FAQ 등록**을 누릅니다.
2. 아래 칸을 채웁니다.
   - **질문**: 고객이 물어볼 법한 문장 (예: `비건 인증 비용은 얼마인가요?`)
   - **다른 표현**: 같은 질문을 다르게 말하는 문장을 **한 줄에 하나씩** (예: `비건인증 얼마`, `비건 인증 가격`)
   - **답변**: **확정된 내용만** 씁니다. (쓰는 요령은 5장)
   - **인증 종류**, **카테고리**: 절차 / 비용 / 기간 / 서류 / 대상·범위 / 갱신 중에서 고릅니다.
   - **출처 URL**: 근거가 되는 홈페이지 주소. 고객에게 '출처' 링크로 보입니다.
3. **상태**를 **승인**으로 하고 저장하면 챗봇이 **바로** 이 FAQ를 사용합니다. 더 다듬어야 한다면 **초안**으로 저장해 두었다가 나중에 승인하세요.
4. 질문을 쓰는 중에 **"비슷한 FAQ가 있습니다"** 경고가 나올 수 있습니다. 같은 내용이면 새로 만들지 말고 기존 FAQ를 고치세요. (경고일 뿐이라 저장을 막지는 않습니다.)

### 4-2. FAQ 고치기, 챗봇에서 내리기, 삭제하기
- **고치기**: FAQ 목록에서 위쪽 검색칸(인증 종류, 카테고리, 상태, 키워드)으로 찾아 질문을 클릭 → 수정 → **저장**. 저장 즉시 챗봇에 반영됩니다.
- **챗봇에서 잠시 내리기**: 상태를 **초안**으로 바꿔 저장합니다. 지우는 것이 아니므로 나중에 다시 승인하면 돌아옵니다. **내릴 때는 삭제보다 이 방법이 안전합니다.**
- **삭제**: **초안 상태의 FAQ만** 삭제할 수 있습니다. 수정 화면 아래쪽 **삭제** 버튼을 누르면 확인 창이 한 번 뜹니다. **승인된 FAQ는 삭제되지 않습니다.** 삭제하면 되돌릴 수 없으니 신중히 하세요.

### 4-3. 여러 건을 한꺼번에 승인하거나 삭제하기
FAQ 목록에서 한 번에 여러 개를 처리할 수 있습니다.
1. 각 FAQ 왼쪽의 **체크 칸**을 눌러 고릅니다. (목록 맨 위의 체크 칸을 누르면 현재 페이지 전체가 선택됩니다.)
2. 목록 아래의 **선택 항목 승인** 또는 **선택 항목 삭제**를 누릅니다.
   - **승인**: 답변이 비어 있거나 '보완 필요'가 켜져 있는 항목은 **자동으로 건너뜁니다.** 몇 건을 건너뛰었는지 화면에 알려 줍니다.
   - **삭제**: 확인 창에 선택한 건수가 표시됩니다. **초안만 삭제**되고, 승인된 FAQ가 섞여 있으면 건너뜁니다.
3. 승인한 FAQ는 목록의 **승인자** 칸에 내 이메일이 남습니다.

### 4-4. 미답변 질문 처리 — 매일 하는 일
챗봇이 답하지 못한 질문은 이곳에 쌓입니다. **이 목록을 비우는 것이 운영의 핵심**입니다.
1. 위쪽 메뉴 **미답변 질문**을 엽니다. (대시보드의 '미처리 미답변 질문' 숫자를 눌러도 됩니다.)
   - **부분 안내** 표시가 있는 질문은 챗봇이 일부만 답하고 나머지를 담당자에게 넘긴 질문입니다. 빠진 부분을 FAQ로 채워 주세요.
   - 챗봇이 인증 종류를 되물어서 고객이 고른 경우에는 질문이 "인증 절차가 어떻게 되나요? / 환경성적표지(EPD)"처럼 **처음 질문과 고른 인증이 함께** 기록됩니다.
2. 질문 오른쪽의 **직접 등록**을 누르면, 그 질문이 미리 채워진 FAQ 등록 화면이 열립니다.
3. **답변, 인증 종류, 카테고리**를 채우고 **저장**합니다. 저장하면 그 미답변 질문은 **자동으로 '처리 완료'** 가 됩니다.
4. FAQ로 만들 필요가 없는 질문(잡담 등)은 **처리 완료** 버튼만 누릅니다. 실수로 눌렀다면 '처리 완료' 탭에서 **미처리로 되돌리기**를 누르세요.
5. 파일에서 초안을 자동으로 만들고 싶으면 **초안 만들기**를 누릅니다(4-5).

### 4-5. 문서(파일)에서 FAQ 초안 만들기 → 확인 → 승인

인증 안내서, 절차서 같은 파일을 올려 두면, 시스템이 **파일 안에서 근거를 찾아 FAQ 초안을 대신 써 줍니다.** 사람이 일일이 쓰는 수고를 크게 줄여 줍니다. 하지만 **확인하고 승인하는 것은 반드시 사람이 합니다.**

```
파일 올리기 → 글자 읽어오기 → FAQ 초안 만들기 → 사람이 확인 → 승인 → 챗봇이 답변
```

**시스템이 지키는 약속**
- **파일은 답변의 근거가 아닙니다.** 챗봇은 파일을 직접 읽어서 답하지 않고, **승인된 FAQ로만** 답합니다. 파일은 FAQ 초안을 쓰는 재료일 뿐입니다.
- 만들어진 초안은 **항상 '초안'** 상태이고, 승인하기 전에는 고객에게 보이지 않습니다.
- 파일에 근거가 없으면 답을 **지어내지 않고**, 답변이 빈 '보완 필요' 초안으로 남겨 둡니다.
- 답변에 들어간 **숫자(비용·기간)와 근거 문장**은 파일 원문과 **글자 그대로 비교**해서, 하나라도 다르면 그 초안은 자동으로 버립니다.
- 컨설팅에 해당하는 내용은 초안으로 만들지 않습니다.

**① 파일 올리기 — 위쪽 메뉴 '문서 보관함'**
1. 파일을 선택합니다(한 번에 최대 20개, 파일 하나당 20MB까지). 그리고 **인증 종류**와 **분류**를 고른 뒤 업로드합니다.
2. **분류**는 절차 / 비용·수수료 / 양식 / 규정·정책 중에서 알맞은 것을 고릅니다. **'기타 (초안 제외)'를 고르면 초안을 만드는 재료로 쓰이지 않습니다.** 챗봇 사용 설명서 같은 내부 문서나 인증 근거가 아닌 자료는 올리지 마세요. (엉뚱한 FAQ가 만들어질 수 있습니다.)
3. **올릴 수 있는 파일**: PDF, DOCX(워드), XLSX(엑셀), PPTX(파워포인트), CSV, TXT, MD. **HWP(한글) 파일은 올릴 수 없습니다.** 한글 프로그램에서 PDF로 저장해서 올려 주세요.
4. 올리면 시스템이 자동으로 **파일 안의 글자를 읽어옵니다.** 상태가 **추출 완료**로 바뀌면 FAQ 초안을 만들 수 있습니다.
5. **스캔한 이미지 PDF**는 글자가 아니라 사진이어서 읽을 수 없고 **추출 실패**로 나옵니다. 이럴 땐 글자가 들어 있는 원본(워드, 파워포인트 등)을 다시 올려 주세요. 실패해도 올린 파일은 보관되며, **재추출** 버튼으로 다시 시도할 수 있습니다.
6. **내용이 똑같은 파일은 다시 올릴 수 없습니다**(이름이 달라도 막힙니다). 이름은 같은데 내용이 다르면 선택 창이 뜨고, **개정판으로 올리기**(기본), 별도 문서로 올리기, 취소 중에서 고릅니다.
7. **문서 형식**을 고릅니다. 일반 설명 글은 **설명 자료**(기본), 질문과 답이 이미 정리된 파일(Q&A 문서)은 **질문·답변 자료**를 고릅니다. 질문·답변 자료는 원문의 질문과 답을 그대로 가져옵니다. 올린 뒤 **형식 확인**을 누르면 처음 3건이 미리보기로 나오고, 맞다고 확인해야 초안을 만들 수 있습니다.

**② 초안 만들기**
- 문서 목록의 해당 파일 줄에서 **FAQ 초안 만들기**를 누릅니다. (여러 파일은 앞의 체크 칸으로 고른 뒤 맨 위의 **선택한 문서 FAQ 초안 만들기**)
- 시간이 걸리며, 화면에 **조각 n/m**(파일을 작게 나눈 조각 중 몇 번째인지)으로 진행 상황이 보입니다. 화면을 닫으면 멈추지만 같은 파일의 **이어서 진행**을 누르면 이어서 합니다.
- 파일 하나에서 만드는 초안은 **최대 50건**입니다. 넘치면 파일을 나눠 올려 주세요.
- 끝나면 **초안 N건 생성 · 탈락 M건**이 표시됩니다. **탈락 목록 보기**에서 시스템이 걸러 낸 항목과 그 이유를 볼 수 있습니다. 자동으로 걸러지는 경우는 ① 근거 문장이 원문에 없음 ② 숫자가 원문과 다름 ③ 컨설팅 내용 ④ IGSC가 하는 일이 아닌 다른 기관 안내 ⑤ 이미 있는 FAQ와 같은 질문입니다.
- 미답변 질문 **한 건**에서 초안을 만들고 싶을 때는 **미답변 질문** 메뉴의 **초안 만들기**를 사용합니다.

**③ 확인하기 — 문서 줄의 '검수하기' 버튼**
문서 목록에는 **생성 n · 승인 n · 미검수 n**이 표시됩니다. **검수하기**를 누르면 그 파일에서 만든 초안을 한 화면에서 차례로 확인할 수 있습니다.
- 각 카드에서 질문과 답변을 **바로 고칠 수 있습니다.** **원문 보기**를 펼치면 답의 근거가 된 문장이 **노란색**으로 표시되니, 원문과 답이 같은 뜻인지 눈으로 비교하세요.
- 카드마다 **인증 종류와 카테고리**도 바꿀 수 있습니다.
- 처리 방법 세 가지: **승인**(고친 내용을 저장하면서 승인, 챗봇에 바로 반영) / **보류**(초안으로 남기고 목록에서 흐리게 표시) / **삭제**(초안만 삭제)
- 화면 아래에서 **일괄 승인·전체 승인**을 할 수 있고, 누르면 "내용을 확인하셨나요?" 확인 창이 한 번 뜹니다. 답변이 비었거나 입력이 필요한 항목은 제외됩니다.
- 키보드로도 처리할 수 있습니다: ↑↓ 이동, A 승인, S 보류, D 삭제.
- **꼭 확인할 것**: 숫자(비용·기간), 대상과 조건, 원문에 없는 문장이 섞여 있지 않은지.
- 별도의 **탈락 탭**에는 걸러진 항목이 이유와 함께 보입니다. **직접 작성**을 누르면 질문과 원문이 채워진 FAQ 등록 화면으로 이동합니다.

### 4-6. 파일 내용이 바뀌었을 때 (재검토)
인증 안내서가 새 버전으로 바뀌면, 그 파일로 만든 FAQ도 다시 확인해야 합니다. 시스템이 알려 줍니다.
1. **문서 보관함**에서 해당 파일의 **개정판 올리기**를 눌러 새 파일을 올립니다. (이전 파일은 '이전 버전'으로 보관됩니다.)
2. 이전 파일로 만든 **승인된 FAQ**에 **재검토 필요** 표시가 자동으로 붙습니다. **이 사이에도 기존 답변은 계속 고객에게 나갑니다**(서비스가 끊기지 않습니다). 대시보드의 "재검토 필요 N건" 카드나 FAQ 목록의 **재검토 필요만** 체크로 모아서 볼 수 있습니다.
3. FAQ를 열고 **새 문서로 초안 다시 만들기**를 누르면 기존 답변과 새 초안이 **나란히** 보입니다(이때는 아무것도 바뀌지 않습니다). 새 초안이 맞으면 **새 초안 내용을 아래 답변 입력란에 채우기** → **저장**. 바꿀 내용이 없으면 **변경 없음 — 재검토 완료**를 누릅니다.
4. 파일을 **삭제**한 경우에도 같은 재검토 표시가 붙습니다. 원문은 더 볼 수 없으니, 다른 자료로 답이 여전히 맞는지 확인해 주세요.

### 4-7. 새 인증 종류 추가하기
새로운 인증을 시작하면 개발자에게 부탁하지 않고 **위쪽 메뉴 '인증 종류'** 에서 직접 추가할 수 있습니다.
- **추가**: 코드(영문 소문자·숫자·하이픈, 예: `pet-related-product`), 한글 이름, 영문 이름(선택), 분류, 정렬 순서를 입력하고 **추가**를 누릅니다. 문서 업로드와 FAQ 등록 화면의 인증 종류 목록에 **바로** 나타납니다. **코드는 한 번 만들면 바꿀 수 없으니** 신중히 정하세요.
- **수정·숨기기**: 이름과 분류를 고치거나 **활성** 체크를 풀고 **저장**하면 새로 등록할 때의 선택 목록에서만 빠집니다. 기존 FAQ와 문서는 그대로 남습니다.
- **공통**은 "모든 인증에 해당하는 내용"을 담는 특별한 항목이라 **고정**으로 표시되고 바꿀 수 없습니다.

### 4-8. 대시보드와 대화 로그 읽는 법
- **답변 성공률** = 답변 완료 ÷ (답변 완료 + 담당자 이관). "챗봇이 답했어야 하는 질문 중 실제로 답한 비율"입니다. 컨설팅 차단, 불만, 범위 밖, 되묻기는 계산에 넣지 않습니다.
- **많이 묻는 질문 Top 10**: 최근 30일 동안 가장 많이 들어온 질문입니다. 이 중 **'담당자 이관'으로 처리된 질문이 FAQ로 만들 1순위**입니다.
- **미처리 미답변 질문**: 0에 가깝게 유지하는 것이 목표입니다.
- **대화 로그**: 대화를 펼치면 챗봇이 실제로 한 말과 **근거로 쓴 FAQ**가 보입니다. FAQ 이름을 누르면 바로 수정 화면으로 갑니다. 고객이 "답이 이상하다"고 하면 여기서 근거 FAQ를 찾아 고치면 됩니다.
- **불만 접수**로 분류된 대화는 **담당자가 직접 읽고 대응**해야 합니다.

### 4-9. 유입 채널 보기 (어느 링크에서 질문이 들어왔나)
챗봇 링크를 여러 곳에 걸어 둘 때, 채널마다 **표시가 붙은 링크**를 쓰면 어디서 얼마나 문의가 들어오는지 알 수 있습니다.
1. 위쪽 메뉴 **유입 채널**을 엽니다. 아래쪽 **채널별 링크 만들기**에 채널마다 링크가 한 줄씩 있습니다. **복사**를 누르면 복사됩니다.
2. 그 링크를 해당 채널에 겁니다 (블로그 글·프로필, 링크드인, 인스타그램 프로필·스토리, 직원 이메일 서명, 홈페이지). 같은 채널에서 게시물이나 직원별로 나누고 싶으면 **캠페인 이름**(예: `story-1010`, `kim`)을 입력하면 링크 뒤에 붙습니다.
3. 고객이 그 링크로 들어와 질문하면 위쪽 표에 집계됩니다. 기간(오늘·최근 7일·최근 30일·전체)을 골라 볼 수 있습니다.

| 표의 항목 | 뜻 |
|---|---|
| 대화 수 | 질문을 한 방문(브라우저 탭)의 수 |
| 질문 수 | 챗봇에 입력된 질문 수 |
| 비중 | 전체 질문 중 이 채널의 비율 |
| 답변 완료 / 담당자 이관 / 불만 | 처리 결과별 건수 |
| 답변 성공률 | 답변 완료 ÷ (답변 완료 + 담당자 이관) |

- **직접 입력·알 수 없음**: 링크에 채널 표시가 없었거나, 링크 단축 서비스가 표시를 지운 경우입니다. 링크를 단축할 때는 표시가 포함된 완성된 링크를 단축하세요.
- 챗봇을 열기만 하고 질문하지 않은 방문은 집계되지 않습니다.
- 대화 로그의 각 대화에도 채널이 작은 표시로 나옵니다.

## 5. FAQ 잘 쓰는 방법

챗봇의 답변 품질은 **FAQ를 얼마나 잘 쓰느냐**에 달려 있습니다.

1. **FAQ 하나에는 질문 하나만.** 여러 질문을 한 FAQ에 섞으면 챗봇이 헷갈립니다.
2. **질문에 인증 이름을 넣으세요.** 이름이 같은 다른 인증(식품 비건 / 화장품 비건)은 어느 분야인지까지 적습니다.
3. **답변은 확정된 사실만.** 비용과 기간은 담당자가 확정한 값과 함께 **기준일**, **금액·기간이 달라지는 조건**(제품 수, 시설 수 등)을 적습니다. 모르면 억지로 쓰지 말고 답변을 비워 두고 '담당자 입력 필요'로 두세요.
4. **'다른 표현'을 충분히 적으세요.** 챗봇은 '질문'과 '다른 표현'을 보고 FAQ를 찾습니다. 대화 로그에서 실제 고객이 쓴 말("비건인증 얼마", "가격이 어떻게 돼요")을 그대로 가져와 추가하면 좋습니다.
5. **출처 URL을 넣으세요.** 고객이 원문을 직접 확인할 수 있어 신뢰도가 올라갑니다.

| | 좋은 FAQ | 고치면 좋은 FAQ |
|---|---|---|
| 질문 | 식품 비건(Vegan) 인증의 원칙은 무엇인가요? | 비건 관련 (너무 넓어서 무엇을 묻는지 알 수 없음) |
| 답변 | 동물 및 동물 유래 성분 금지, 동물 실험 금지, 교차 오염 금지의 세 가지 원칙입니다. | 보통 3~4주 걸립니다 (근거 없는 짐작) |

**FAQ에 넣으면 안 되는 것**
- **컨설팅 내용** (통과하는 방법, 기준 맞추는 법, 준비·개선 조언). 이런 질문은 챗봇이 FAQ를 보지도 않고 거절하지만, 이런 FAQ가 승인돼 있으면 다른 질문 답변에 섞여 나갈 위험이 있습니다.
- **짐작이나 일반 상식** ("보통", "대략", "일반적으로" 같은 표현)
- **개인정보**, 다른 기관의 정보

**승인 전 체크리스트** — 승인 버튼을 누르기 전에 확인하세요.
- [ ] 질문이 하나의 주제이고, 어떤 인증인지 드러난다
- [ ] 답변의 모든 내용이 공식 자료 또는 담당자가 확정한 값과 같다
- [ ] 비용·기간이면 기준일과 달라지는 조건을 적었다
- [ ] 컨설팅처럼 읽히는 표현이 없다
- [ ] 출처 URL과 '다른 표현'이 있다

> **FAQ가 많아지면?** FAQ가 많아질수록 챗봇이 FAQ를 고르는 데 시간이 조금 더 걸리고 AI 사용 비용이 늘어납니다. 지금 방식은 FAQ가 수백 건이어도 문제없이 동작하는 것을 확인했습니다. 승인된 FAQ가 **약 500건을 넘으면** 응답 속도와 비용을 점검해야 하니 개발사에 문의해 주세요. 점검 결과에 따라 검색 방식을 개선할 수 있습니다.

## 6. 운영 루틴과 운영 상태

### 6-1. 언제, 무엇을 할까요?

| 주기 | 할 일 | 걸리는 시간 |
|---|---|---|
| **매일** | 대시보드에서 '미처리 미답변 질문'을 확인하고 FAQ로 만들거나 '처리 완료'로 표시합니다. **불만 접수** 대화가 있는지도 봅니다. | 5분 |
| **문서가 바뀔 때** | 개정판을 올리고 → '재검토 필요'를 확인하고 → 각 FAQ를 새 문서와 비교해 고치거나 '변경 없음'으로 처리합니다. | 그때그때 |
| **매주** | 많이 묻는 질문 Top 10을 보고, 담당자 이관이 많은 질문을 FAQ로 만듭니다. 답변 성공률이 오르는지 봅니다. '답변 완료' 몇 건을 골라 답이 정확한지 확인하고, 고객이 쓴 실제 표현을 '다른 표현'에 추가합니다. | 30분 |
| **매달** | 오래되었거나 중복된 FAQ를 정리합니다(초안으로 내리기). 출처 링크가 살아 있는지 확인합니다. 대화 기록에 개인정보가 들어 있지 않은지 살펴봅니다. 관리자 목록에서 퇴사자를 뺍니다. | 1시간 |
| **제도·비용·기간이 바뀔 때** | 해당 FAQ를 **바로 고치고 저장**합니다(즉시 반영). 옛 내용으로 답한 대화가 없는지 대화 로그에서 확인합니다. | 그때그때 |

### 6-2. 운영 상태 화면 — 챗봇이 건강한지 확인하기
위쪽 메뉴 **운영 상태**를 열 때마다 시스템이 **데이터 저장소와 AI에 실제로 연결해 보고** 결과를 보여 줍니다. 최근 1시간의 오류, 오늘 받은 질문 수(하루 상한 3,000건 대비), 승인된 FAQ 수, 처리 대기 중인 미답변 질문 수도 함께 나옵니다.

| 상태 | 의미 |
|---|---|
| **정상** (초록) | 문제가 없습니다. |
| **주의** (노랑) | 당장 멈추지는 않았지만 살펴봐야 합니다. 예) 승인된 FAQ가 0건, 오늘 질문 수가 하루 상한의 80%, 미답변 질문 30건 이상 |
| **긴급** (빨강) | 챗봇이 제대로 일하지 못하고 있습니다. 예) AI 연결 실패(AI 사용 크레딧이 떨어졌거나 키에 문제가 있을 때), 데이터 저장소 연결 실패, 최근 1시간 오류가 갑자기 많음, 하루 상한 도달 |

- **'긴급'이 보이면 챗봇이 모든 질문을 "담당자 확인이 필요합니다"로 처리하고 있을 수 있습니다.** 바로 개발사에 알려 주세요. (실제로 AI 크레딧이 떨어졌을 때 이렇게 보였습니다.)
- 시스템이 **하루에 한 번(오전 9시)** 자동으로 점검하고, 문제가 있으면 **관리자 이메일로 알림 메일**을 보냅니다. 이 메일이 스팸함에 들어갈 수 있으니, 처음 받으면 **'스팸 아님'으로 표시**해 두세요.

## 7. 실습 시나리오

교육 시간에 아래 순서대로 직접 해 봅니다. 실습용 FAQ에는 질문 앞에 `[실습]`을 붙이세요.

| # | 해 볼 것 | 확인할 것 |
|---|---|---|
| 1 | `[실습]` FAQ 1건을 **초안**으로 만든다 → 챗봇에서 같은 질문을 해 본다 → FAQ를 **승인**한다 → 다시 질문한다 | 초안일 때는 답하지 않고, 승인하면 바로 답한다 |
| 2 | 챗봇에 FAQ에 없는 질문을 한다 → **미답변 질문**에 쌓였는지 본다 → **직접 등록**으로 FAQ를 만든다 | 저장하면 그 미답변이 자동으로 '처리 완료'가 된다 |
| 3 | 실습 FAQ를 **초안으로 내린다** → 챗봇에서 확인 → 체크 칸으로 여러 건 **삭제**해 본다 | 승인된 FAQ는 삭제되지 않는다 |
| 4 | 문서 보관함에서 파일 1개의 **FAQ 초안 만들기** → **검수하기** → 원문 보기로 비교 → 1건 승인, 1건 보류 | 승인한 사람의 이메일이 남는다 |
| 5 | 비용 FAQ 중 '보완 필요'인 항목을 열어 답변을 쓴다 → 승인한다 | '담당자 입력 필요'를 해제해야 승인된다 |
| 6 | 대화 로그에서 방금 나눈 대화를 찾아 **근거 FAQ**로 이동해 본다 | 답이 이상하면 근거 FAQ를 고치면 된다 |
| 7 | **운영 상태** 화면을 열어 본다 | 정상·주의·긴급의 의미를 이해한다 |

**실습이 끝나면** `[실습]`이 붙은 FAQ를 모두 초안으로 되돌리거나 삭제해 주세요.

## 8. 문제가 생겼을 때

| 이런 일이 생기면 | 이렇게 확인하세요 |
|---|---|
| FAQ를 저장했는데 챗봇이 예전 답을 한다 | FAQ **상태가 '승인'** 인지, '담당자 입력 필요'가 꺼져 있는지 확인하세요. 고객의 말투가 FAQ와 많이 다르면 **다른 표현**에 그 말투를 추가하세요. |
| 승인이 안 된다 | 답변이 비어 있거나 '담당자 입력 필요'가 켜져 있는 경우입니다. 이유가 화면에 표시됩니다. |
| 챗봇이 엉뚱한 FAQ로 답한다 | 대화 로그에서 근거로 쓴 FAQ를 확인하고, 질문을 더 구체적으로(인증 이름 포함) 고치거나 초안으로 내리세요. |
| 답해야 할 질문에 계속 "담당자 확인"이라고 나온다 | 미답변 질문에서 FAQ로 만드세요. |
| 비용·기간이 안 나온다 | 해당 FAQ가 '보완 필요'(답변이 비어 있음) 상태입니다. 확정된 값을 입력하고 승인하세요. |
| 파일을 올렸는데 초안이 안 만들어진다 | 상태가 **추출 완료**인지, 분류가 '기타'가 아닌지 확인하세요. 스캔한 PDF는 글자가 있는 원본으로 다시 올리세요. |
| 같은 파일이 올라가지 않는다 | 내용이 같은 파일은 올릴 수 없습니다. 이미 올라가 있는 파일을 알려 줍니다. |
| HWP 파일이 올라가지 않는다 | 지원하지 않는 형식입니다. 한글에서 PDF로 저장해 올리세요. |
| 초안이 답변 비어 있는 '보완 필요'로 만들어졌다 | 파일에 근거가 없거나 검증에서 탈락한 경우입니다. 목록의 이유를 보고 직접 쓰세요. |
| "컨설팅 요청이라 초안을 만들지 않았습니다"가 나온다 | 정상 동작입니다(공평성 원칙). 담당자가 직접 판단해 응대합니다. |
| 인증 종류 목록에 없는 인증이다 | **인증 종류** 메뉴에서 직접 추가하세요. |
| 로그인 링크가 열리지 않는다 | 링크를 요청한 **같은 브라우저**에서 열었는지, 오래된 링크가 아닌지 확인하고 다시 요청하세요. 스팸함도 확인하세요. |
| 챗봇이 계속 "일시적인 문제로 답변을 드리지 못했습니다"라고 한다 | **운영 상태** 화면을 확인하세요. **긴급**이면 개발사에 바로 연락하세요. |
| 고객이 "잠시 후 다시 시도해 주세요"를 본다 | 짧은 시간에 너무 많은 요청이 몰려 잠시 제한된 것입니다. 잠시 뒤 정상으로 돌아옵니다. 계속되면 개발사에 문의하세요. |

**알아 두면 좋은 현재 한계**
- 비슷한 제품의 인증 사례(인증 이력)는 관리자 화면에서 입력할 수 없고, 개발사가 데이터 저장소에 직접 넣습니다.

## 부록. 용어 정리

| 용어 | 뜻 |
|---|---|
| FAQ | 질문과 답변 한 쌍. 챗봇이 답하는 유일한 근거 |
| 승인 / 초안 | 승인된 FAQ만 챗봇이 사용. 초안은 작업 중인 상태 |
| 보완 필요 | 답변이 아직 없는 FAQ (`담당자 입력 필요` 표시) |
| 다른 표현 | 같은 질문의 다른 말투. 챗봇이 FAQ를 찾는 데 쓰임 |
| 공통 | 모든 인증에 해당하는 FAQ(절차, 서류, 로고 사용 등)를 담는 인증 종류 값 |
| 담당자 이관 | 챗봇이 답하지 않고 사람에게 넘기는 처리 |
| 부분 안내 | FAQ로 답할 수 있는 부분까지만 답하고 나머지를 담당자에게 넘긴 처리 |
| 미답변 질문 | 담당자에게 넘어간 질문이 모이는 목록. FAQ를 늘리는 출발점 |
| 재검토 필요 | 근거 파일이 새 버전으로 바뀌었거나 삭제된 승인 FAQ에 붙는 표시. 확인하는 동안에도 답변은 계속 나감 |
| 조각(청크) | 파일을 FAQ 초안 만들기 좋게 잘게 나눈 부분 |
| 추출 | 파일 안의 글자를 읽어오는 것 |
