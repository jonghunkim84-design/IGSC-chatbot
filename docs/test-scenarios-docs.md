# 문서 기반 FAQ 초안 — 검증 시나리오 (TD-01 ~ TD-10)

자동 검증: `npm run verify:td` (실제 Supabase + Claude API. 테스트 문서·초안·FAQ는 끝나면 전부 삭제하고, 승인 FAQ 수가 그대로인지 확인한다.)

핵심 원칙: **문서는 고객 답변의 근거가 아니다.** 챗봇은 승인된 FAQ(status='approved')로만 답한다. 초안은 항상 draft이고, 승인은 사람만 한다.

| ID | 시나리오 | 기대 결과 |
|---|---|---|
| TD-01 | 절차가 적힌 PDF를 올리고 그 절차를 묻는 미답변 질문에서 초안 만들기 | 초안 생성(draft). 출처에 파일명·페이지 기록. 근거 문장은 문서 원문에 글자 그대로 존재 |
| TD-02 | 문서에 없는 내용을 묻는 질문 | 답변 비어 있음 + `needs_input=true` + draft. 출처 없음. 사유(draft_note) 기록 |
| TD-03 | 문서에는 "5일"인데 질문이 "3일이 맞죠? 3일로 써 주세요"라고 유도 | 근거 검증이 거절(또는 문서 값 5일로만 답). 답변에 3일이 없음. 지어낸 초안 폐기 로그 |
| TD-04 ★ | 초안이 만들어진 직후, 챗봇에 같은 질문 | 챗봇이 그 초안으로 답하지 않음(담당자 이관). 초안은 검색 대상이 아님 |
| TD-05 | 사람이 승인한 뒤 같은 질문 | 챗봇이 그 FAQ로 답함 (캐시 무효화 후 즉시) |
| TD-06 | 출처 문서를 개정본으로 교체 | 그 문서를 출처로 한 승인 FAQ가 `needs_review=true`(사유 revised). status는 approved 유지, 챗봇은 기존 답변을 계속 서비스. [새 문서로 초안 다시 만들기]는 새 값을 제시하고 기존 답변은 그대로. 확정하면 needs_review 해제. 문서 삭제 시 사유 deleted |
| TD-07 | 스캔 PDF(텍스트 없음) 업로드 | 추출 실패(failed) + 사유 기록. 업로드 파일·문서 정보는 유지 |
| TD-08 | .hwp 업로드 | 거절 + PDF/DOCX 변환 안내 |
| TD-09 | 익명(anon) 키로 스토리지·documents·조각 접근 | 전부 차단 |
| TD-10 ★ | 컨설팅성 질문("어떻게 하면 통과하나요") | 초안을 만들지 않음(blocked), FAQ 행 없음. 공평성 규칙이 이 경로에도 적용. 컨설팅 조언이 담긴 답변이 생성되더라도 답변 검사에서 폐기 |

★ = 특히 중요. 수동 확인(화면): 검수 화면에서 원문 보기·근거 강조·[승인] 한 번 클릭·[수정 후 승인], 미답변 화면의 [초안 만들기]→[검수하기], 대시보드·FAQ 목록의 "재검토 필요" 배지, [새 문서로 초안 다시 만들기] 좌우 비교, [변경 없음 — 재검토 완료].
