# 운영 모니터링

챗봇이 조용히 멈추는 일(API 크레딧 소진, DB 장애 등)을 사람이 묻기 전에 알아채기 위한 장치입니다.
실제로 크레딧이 떨어졌을 때 챗봇은 모든 질문을 "담당자 이관"으로 처리했고, 겉으로는 정상처럼 보였습니다.

## 구성
| 장치 | 위치 | 용도 |
|---|---|---|
| 운영 상태 화면 | 관리자 → **운영 상태** (`/admin/status`) | 열 때마다 DB·AI 연결을 실제로 확인하고, 최근 1시간 오류·오늘 질문 수·승인 FAQ·미답변 적체를 보여줌 |
| 헬스체크 | `GET /api/health` | 외부 가동 감시(UptimeRobot 등)용. DB·AI 모두 정상이면 200, 아니면 503. 세부 오류는 노출하지 않음. AI 점검은 5분간 결과 재사용 |
| 자동 점검 + 알림 | `GET /api/cron/monitor` (하루 1회 09:00 KST, `vercel.json`) | 문제를 판정하고 관리자 이메일(·웹훅)로 알림. 같은 문제는 6시간에 한 번만 |

## 알림이 나가는 문제
| 코드 | 수준 | 조건 |
|---|---|---|
| `ai-down` | 긴급 | AI 호출 실패 (크레딧 소진·키 오류·장애) |
| `db-down` | 긴급 | DB 연결 실패 |
| `chat-errors` | 긴급 | 최근 1시간 대화 중 오류 이관이 3건 이상이고 20% 이상 |
| `daily-cap` | 긴급 | 오늘 질문 수가 하루 상한(기본 3000)에 도달 → 새 질문 거절 중 |
| `daily-near` | 주의 | 하루 상한의 80% |
| `no-approved-faq` | 주의 | 승인 FAQ 0건 (인계 직후에는 정상) |
| `unanswered-backlog` | 주의 | 미답변 대기 30건 이상 |

기준값은 `lib/monitor/evaluate.ts` 의 `DEFAULT_THRESHOLDS`.

## 설정 (Vercel 환경변수)
1. `CRON_SECRET` — 임의의 긴 문자열. 설정해야 자동 점검이 동작한다 (없으면 503).
2. **이메일 알림** — 수신자는 관리자 이메일 목록(`ADMIN_ALLOWED_EMAILS`)이다. 메일 발송은 Resend(resend.com) 를 쓴다: 계정을 만들고 API 키를 `RESEND_API_KEY` 로 등록. 기본 보내는 주소(`onboarding@resend.dev`)는 **Resend 계정 가입 이메일로만** 발송된다. 관리자 3명 모두에게 보내려면 Resend 에서 회사 도메인을 인증하고 `ALERT_EMAIL_FROM`(예: `IGSC 챗봇 <alert@회사도메인>`)을 등록한다.
3. (선택) `ALERT_WEBHOOK_URL` — Slack 의 Incoming Webhook 주소. 이메일과 함께 쓸 수 있다.
(이메일 키·웹훅이 모두 없으면 알림은 Vercel 로그에만 남는다.)
4. (권장) 외부 가동 감시 서비스에 `https://<도메인>/api/health` 를 등록 (5분 간격, 503 이면 이메일 알림).
5. (권장) Anthropic 콘솔(Settings > Billing)에서 자동 충전과 월 지출 한도 설정 (한도에 닿아도 챗봇이 멈추므로 넉넉하게) — 크레딧 소진을 가장 빨리 막는 방법.

## 참고
- 자동 점검은 실행할 때마다 모델을 1토큰 호출한다 (비용은 사실상 0).
- 현재 Vercel Hobby 요금제라 자동 점검은 하루 1회만 가능하다 (Pro 요금제면 `vercel.json` 의 주기를 `*/30 * * * *` 로 바꾼다). 그래서 실시간 감시는 외부 가동 감시 서비스가 `/api/health` 를 5분마다 확인하는 방식(위 4번)을 함께 쓴다.
