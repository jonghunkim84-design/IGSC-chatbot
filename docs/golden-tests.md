# 대표 질문 회귀 테스트

챗봇을 고치거나(프롬프트·분류·검색·FAQ 대량 변경) 배포하기 전에 "예전에 되던 것이 여전히 되는가"를 실제 모델과 실제 승인 FAQ 로 확인한다.

## 실행
```bash
npm run golden                      # 전체 (질문 42건, 실제 모델 호출)
npm run golden -- --safety          # FAQ 와 무관한 안전 규칙만 (승인 FAQ 가 0건이어도 통과해야 함)
npm run golden -- --filter F0       # id 또는 질문에 글자가 들어간 것만
npm run golden -- --repeat 3        # 각 질문을 3번 (모델 답이 흔들리는 질문 찾기)
npm run golden -- --out docs/golden-report.md
```
- DB 에 쓰지 않는다 (채팅 기록·미답변에 남지 않음). 모델 호출 비용은 질문당 일반 챗봇 질문과 같다. `--repeat` 는 그만큼 곱절이다.
- 시작할 때 모델 호출이 되는지 먼저 확인한다. API 크레딧 소진·키 오류면 종료 코드 2 로 멈춘다.
- 결과: PASS / FAIL / FLAKY(반복 중 일부만 실패). 실패·흔들림이 있으면 종료 코드 1.

## 무엇을 검사하나
| 구분 | 검사 |
|---|---|
| 처리 경로 | 질문마다 허용된 경로(answered / consulting_blocked / complaint / out_of_scope / handoff / clarify) |
| 근거 FAQ | answered 일 때 선택된 FAQ 질문이 기대 주제(정규식)에 맞는가 |
| 금지 표현 | 통과 보장, 인증 가능 확답, 프롬프트 노출, 주입된 금액("50만원") |
| 숫자 불변식 (모든 질문) | 답변의 숫자는 근거 FAQ·고정 문구(연락처 등)·질문에 있는 것만. 비용·기간을 지어내지 않는다는 규칙의 기계 검사 (연도 20xx 는 이력 안내 때문에 제외) |

답변 문장 자체는 고정하지 않는다 (모델이 매번 표현을 바꿈).

## 케이스 관리
`tests/golden/cases.ts` 한 파일. `tag: "safety"` 는 FAQ 와 무관한 규칙, `"faq"` 는 해당 주제 FAQ 가 승인돼 있어야 통과.
- FAQ 문구를 고쳐서 FAQ 케이스가 실패하면: 정규식(`faq`)을 새 문구에 맞게 고친다.
- 실제 고객 문의에서 오답이 나오면: 그 질문을 케이스로 추가한 뒤 고친다 (같은 문제의 재발 방지).
- 고객 인계 시 승인을 0건으로 되돌리므로, 인계 직후에는 `--safety` 만 통과해야 하고, 고객이 FAQ 를 승인한 뒤 전체를 돌린다.

## 언제 돌리나
프롬프트(`lib/prompts/`)·분류·검색 코드를 바꾼 뒤, 모델 버전을 바꾼 뒤, FAQ 를 대량 승인·수정한 뒤, 배포 전.
