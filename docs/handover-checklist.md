표기: 🤖 = 개발 담당(Claude)이 실행 가능 · 👤 = 담당자가 직접 · 🏢 = 고객 결정/확인 필요

## 1. 챗봇에 나가는 내용 (가장 먼저 확인)

- [ ] 🏢 **공개 동의 확인**: 인증 이력을 챗봇이 "공개에 동의한 사례"로 안내해도 되는지 고객 확인. 확인 전에는 비공개로 인계.
- [x] 🤖 **FAQ 승인 되돌리기** (440건 → 0건) — 10/4 실행 완료. 이후 테스트로 다시 승인했다면 인계 직전에 다시 실행
  ```bash
  npx tsx scripts/reset-faq-approval.ts            # 미리보기 (현재 승인 건수, 백업 경로)
  npx tsx scripts/reset-faq-approval.ts --apply    # 백업 저장 후 approved → draft
  ```
  백업은 `data/backup/faq-approved-<시각>.json`(id·질문·승인자 기록 포함). 고객이 "이 항목은 승인해도 된다"고 하면 해당 id만 복원할 수 있다:
  `npx tsx scripts/reset-faq-approval.ts --restore <백업파일> --apply`
- [ ] 🤖 **인증 이력 비공개**: `npm run ingest:history:public -- off` (공개 동의 확인 후 `-- on`)
- [ ] 👤 되돌린 뒤 챗봇에서 아무 질문이나 해서 **모든 질문이 담당자 연결 안내**로 나오는지 확인 (승인 FAQ 0건이면 정상)
  - 인증 이력 안내 문구("공개에 동의한 사례")가 나오지 않는지 확인

## 2. 테스트 데이터 정리

- [x] 🤖 **미답변 질문**: 전부 테스트 질문이면 삭제 — `npx tsx scripts/delete-unanswered-before.ts 2026-10-04` (미리보기 후 `--apply`, 삭제 전 `data/backup/`에 백업)
- [x] 🏢/🤖 **대화 기록** (10/4 전체 삭제함. 인계 직전 점검용 질문이 남았다면 다시 `--all`): 개발 테스트 기록이다. 인계 후 운영 지표(답변 성공률 등)에 섞이지 않도록 비울지 결정. 비우려면 `npx tsx scripts/delete-chat-log.ts --all`(미리보기) → `--apply`(백업 저장 후 삭제). 날짜 지정도 가능: `npx tsx scripts/delete-chat-log.ts 2026-10-04`. 대시보드 통계도 함께 비워진다.
- [x] 👤 **문서 보관함의 테스트 문서** (`반려동물용 인증.md` 삭제함): `반려동물용 인증.md`(개발 검증용) 등 인증 근거가 아닌 문서 삭제. 고객 제공 문서는 유지.
- [ ] 👤 **FAQ 목록 점검**: `승인`이었던 항목 중 질문에 "비건 인증 원칙이 뭔지, 그리고 클린뷰티 인증과 뭐가 다른지"처럼 **테스트로 생긴 FAQ**가 없는지 확인(미답변 → 초안 만들기로 생긴 항목). 있으면 삭제.
- [ ] 🤖 (선택) 문서 초안 작업 기록 2건 삭제 — 화면에는 요약만 보이고 기능에는 영향 없음.
- [ ] 🤖 **개발 문서 정리**: `docs/dev-approved.md`(개발용 임시 승인 10건 기록)는 옛 기록이라 인계 자료에서 제외하거나 삭제.

## 4. 계정·접근·인프라

- [ ] 🏢 **관리자 3명 확정**: Vercel 환경변수 `ADMIN_ALLOWED_EMAILS`에 실제 운영 담당자 이메일만 남기고, 개발·테스트 계정을 뺀다. 목록 변경은 개발사 요청 사항.
- [ ] 🏢 **소유권 이전**: Vercel 프로젝트(`igsc-chatbot`), Supabase 프로젝트, Anthropic API 키의 명의와 결제 주체. 이전 후 **API 키·서비스 키 재발급**(개발 중 사용한 키 폐기).
- [ ] 🏢 **정식 도메인 연결**과 유지 책임 (현재 `igsc-chatbot.vercel.app`). 연결 시 Supabase Redirect URLs에 새 주소의 `/admin/auth/callback` 추가, 환경변수 `NEXT_PUBLIC_SITE_URL` 등록.
- [ ] 🏢 **로그인 메일 한도**: 기본 메일은 시간당 발송 한도가 낮아 자체 SMTP 연결 권장.
- [x] 🤖 **요청 제한(rate limit)**: 적용됨 — 채팅 IP당 분당 15·시간당 120·전체 하루 3000건, 관리자 로그인 메일 IP당 10·이메일당 5(시간당). 한도 조정은 환경변수 (`docs/deploy.md`). 한 사무실 IP를 여러 명이 쓰면 시간당 값을 올린다.
- [ ] 🏢 **월 AI 사용량 상한**과 Anthropic 콘솔(Settings > Billing)의 **월 지출 한도·자동 충전** 설정 (크레딧이 소진되면 챗봇이 모든 질문을 담당자 이관으로 처리한다 — 개발 중 실제로 발생)
- [ ] 🏢 **알림 메일 발신 도메인 인증** (Resend): 회사 도메인을 Resend 에 등록하고 DNS 레코드(도메인 담당자가 추가)를 입력한 뒤 환경변수 `ALERT_EMAIL_FROM` 에 `IGSC 챗봇 <alert@회사도메인>` 등록. 지금은 테스트 발신 주소라 ① 스팸함으로 들어가고 ② Resend 가입 이메일 외에는 발송되지 않는다. 관리자 3명이 확정되면(`ADMIN_ALLOWED_EMAILS`) 전원이 받는지 시험 메일로 확인.
- [ ] 🏢/🤖 **Resend 계정·API 키 명의 이전과 재발급**: 개발 중 사용한 키(`RESEND_API_KEY`)는 폐기하고 고객 명의 계정의 새 키를 Vercel 환경변수에 등록. `CRON_SECRET` 도 재발급.
- [ ] 🏢 **외부 가동 감시 등록**: UptimeRobot 등에서 `https://<도메인>/api/health` 를 5분마다 확인(503 이면 이메일). Vercel Hobby 요금제는 자동 점검이 하루 1회(오전 9시)뿐이라 실시간 감시는 이쪽이 맡는다. Pro 요금제로 올리면 `vercel.json` 크론 주기를 `*/30 * * * *` 로 변경.
- [ ] 👤 **운영 상태 화면 확인**: 관리자 → 운영 상태에서 DB·AI 정상, 알림 수신 확인 (`docs/monitoring.md`)
- [ ] 🏢 **담당자 연락처·상담 신청 링크**(현재 02-858-4321 / igsc@igsc.kr)가 맞는지 확인. 변경 시 `lib/prompts/messages.ts`.

## 6. 최종 점검 (인계 직전, 위 정리를 끝낸 뒤)

- [ ] 🤖 타입 검사·테스트·빌드: `npx tsc --noEmit`, `npx vitest run`, `npm run build`
- [ ] 🤖 대표 질문 회귀 테스트: 인계 직후에는 `npm run golden -- --safety`(FAQ 없이도 통과해야 함). 고객이 FAQ 를 승인한 뒤에는 전체 `npm run golden` (`docs/golden-tests.md`)
- [ ] 🤖 마이그레이션 적용 확인: 0001~0012 (`docs/deploy.md` 참고). 0010 이후 `npx tsx scripts/backfill-content-hash.ts --apply` 완료.
- [ ] 👤 관리자 화면 점검: FAQ / 미답변 / 문서 보관함(업로드·형식 확인·FAQ 초안 만들기) / 검수하기 / 인증 종류 / 대화 로그 각 화면이 열리는지
- [ ] 👤 챗봇 화면 점검: 승인 0건일 때 모든 질문이 담당자 연결로 나오는지, 연락처 문구, 상담 신청 버튼
- [ ] 👤 **고객이 처음 승인할 때의 흐름**을 한 번 시연: 검수하기 → 수정 → 승인 → 챗봇 반영 → 승인자 확인
- [ ] 🤖 운영 배포 상태 확인 (`https://igsc-chatbot.vercel.app`), 환경변수에 `SEARCH_DEBUG_ENABLED`가 설정되어 있지 않은지 확인

## 8. 인계 후 첫 주 권장 루틴

1. 매일: 미답변 질문 화면 확인 — **부분 안내** 건과 **전혀 못 답함** 건을 나누어 처리

4. 문서가 바뀌면 **개정판 올리기** → 대시보드 "재검토 필요" 처리
