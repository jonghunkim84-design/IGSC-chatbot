이 문서는 챗봇 시스템을 **넘겨받아 직접 운영하시는 분**을 위한 안내서입니다. 컴퓨터 설정이나 개발 지식이 많지 않아도 따라 할 수 있도록, **무엇을 준비하고, 어떻게 설치하고, 넘겨받는 날 무엇을 확인하는지**를 순서대로 설명합니다.

> 최종판(final) · 기준일 2026-10-07 · 관리자 화면 사용법은 별도의 「운영자 매뉴얼 (final)」을 보세요. 이 문서는 **시스템 자체를 넘겨받는 방법**과 **챗봇 링크를 채널에 연결하는 방법(9장)** 을 다룹니다.

> **외부 서비스 정보의 기준**: Vercel, Supabase, Claude Code, Anthropic의 요금·제한·설치 방법은 **2026-10-04에 공식 문서를 확인**해서 적었습니다 (출처는 부록 C). 서비스 정책은 바뀔 수 있으니 계정을 만들거나 결제하기 직전에 한 번 더 확인하세요.

## 1. 무엇을 넘겨받나요?

챗봇은 한 덩어리가 아니라, **여러 서비스가 함께 일하는 구조**입니다. 각 서비스는 별도의 회사가 제공하고, **회사(IGSC) 명의의 계정**으로 사용하셔야 합니다.

| 구성 요소 | 하는 일 | 서비스 | 비용 |
|---|---|---|---|
| **서버** | 챗봇 화면과 관리자 화면을 인터넷에 띄워 줍니다. | **Vercel** | Pro: 사용자(좌석) 1명당 월 $20 (2026-10 확인) |
| **데이터 저장소** | FAQ, 대화 기록, 문서 파일을 보관합니다. | **Supabase** | Pro: 월 $25부터 (2026-10 확인) |
| **AI** | 챗봇이 질문을 이해하고 답을 쓸 때 씁니다. | **Anthropic (Claude)** | 사용한 만큼 (크레딧 충전) |
| **알림 메일** | 장애가 생기면 관리자에게 메일을 보냅니다. | **Resend** | 소량은 무료 |
| **소스 코드 보관** | 시스템의 프로그램 코드를 보관하고 변경 이력을 남깁니다. | **GitHub** | 비공개 저장소는 무료 가능 |
| **도메인** | 챗봇 주소(예: chat.회사도메인) | 회사가 쓰는 도메인 업체 | 연 비용 |

```
고객 → 홈페이지의 챗봇 버튼 → [Vercel 서버] ↔ [Supabase 저장소]
                                        ↕
                                  [Anthropic AI]      장애 시 → [Resend] → 관리자 메일
```

> **왜 회사 명의여야 하나요?** 계정 주인이 개인이면 그 사람이 퇴사하거나 연락이 끊겼을 때 서비스를 잃을 수 있습니다. 회사 공용 이메일(예: it@회사도메인)로 가입하고, **소유자(Owner)를 2명 이상** 두세요.

### 인수의 큰 흐름

1. **준비** — 계정을 만들고 컴퓨터에 프로그램을 설치합니다 (이 문서의 2~5장).
2. **인수일** — 개발 담당자와 함께 서버·저장소·키를 회사 계정으로 옮기고, 정상 동작을 확인합니다 (6장).
3. **운영** — 평소 운영, 비용 관리, 문제 대응 (7~8장).

## 3. 계정 만들기

> 아래 화면 구성과 요금제 이름은 서비스 회사가 바꿀 수 있습니다. 헷갈리면 각 서비스의 도움말을 함께 보세요.

### 3-1. 모든 계정에 공통으로 하세요
1. **회사 공용 이메일**로 가입합니다.
2. **2단계 인증**(휴대폰 앱이나 문자 인증)을 켭니다.
3. 가입 후 **소유자(Owner)를 2명**으로 합니다. 책임자와 보조 담당자를 초대하세요.
4. 비밀번호는 비밀번호 관리 프로그램에 보관하고, 메신저나 메일로 주고받지 않습니다.

### 3-2. Vercel (서버)
1. vercel.com에서 회사 이메일로 가입합니다.
2. **Pro 요금제**로 올리고 결제 수단을 등록합니다. 무료(Hobby) 요금제는 **비상업·개인용으로만 허용**되고, 자동 점검(크론)이 하루 1회로 제한됩니다. 업그레이드는 Settings → Billing → Plan의 **Upgrade**에서 하며, 화면에 따라 **Create a Team**(팀 만들기)을 먼저 해야 할 수 있습니다.
3. Pro는 **사용자(개발자 좌석) 1명당 월 $20**이고, 열람만 하는 사용자(Viewer)는 무료입니다. 서버에 배포하는 사람(책임자·보조)만 좌석으로 두면 됩니다. 관리자 화면 사용자는 Vercel 계정이 필요 없습니다.

### 3-3. Supabase (데이터 저장소)
1. supabase.com에서 가입하고 **조직(Organization)** 을 만듭니다. 조직 이름은 회사 이름으로 하세요.
2. 조직을 **Pro 요금제**(월 $25부터)로 하고 결제 수단을 등록합니다. **무료 프로젝트는 1주 동안 사용하지 않으면 일시 정지**되고, 그러면 챗봇이 멈춥니다. Pro는 사용이 없어도 정지되지 않고, 일일 백업을 7일간 보관합니다.
3. 인수일에 개발 담당자가 프로젝트를 이전할 수 있도록, **개발 담당자를 그 조직에 **조직 전체 역할**의 **관리자(Administrator) 또는 소유자(Owner)** 로 초대**해 두세요. 초대하는 방법: Supabase 대시보드에서 **고객 조직**을 선택하고 조직 설정의 **Team** 메뉴에서 개발 담당자의 이메일을 입력해 역할을 고릅니다(초대 메일은 **24시간 안에 수락**해야 하니 인수일에 보내세요). 초대할 때 프로젝트 하나에만 주는 **프로젝트 단위 역할은 쓰지 마세요**(이전이 막힙니다). (Supabase는 이전을 시작하는 쪽이 원래 조직의 소유자이고, 받는 조직에서는 멤버 이상이면 됩니다.) 이전이 끝나면 권한을 뺍니다.
4. 이전할 때 **Supabase의 GitHub 연동, 로그 드레인, 프로젝트 단위 역할**이 켜져 있으면 이전이 막힙니다. 이 시스템은 쓰지 않으니 새로 켜지 마세요. 또 **지역(리전)이 다른 조직으로는 이전할 수 없습니다.**

### 3-4. Anthropic Console (AI)
1. Claude Console(platform.claude.com)에서 가입하고 조직을 만듭니다.
2. **결제 수단을 등록하고 크레딧을 충전**합니다. **AI 크레딧이 떨어지면 챗봇이 모든 질문에 "담당자 확인"으로 답합니다.**
3. **Settings → Billing**에서 두 가지를 정합니다.
   - **자동 충전(auto-reload)**: 잔액이 정한 금액 밑으로 내려가면 자동으로 충전합니다(선택).
   - **월 지출 한도(Spend limits → Set limit)**: 이 한도에 닿으면 **챗봇도 멈춥니다.** 한도는 예상 사용량보다 넉넉하게 정하세요.
   새 조직은 **한도가 낮은 시작 단계(Evaluation)** 에서 시작할 수 있고, 사용 이력이 쌓이면 자동으로 올라갑니다. 질문이 몰리는 시기가 예상되면 미리 준비하세요.
4. **API 키**를 만듭니다. 인수일에 서버에 입력할 키이며, 만든 직후 한 번만 보이니 안전한 곳에 복사해 두세요.

### 3-5. Resend (알림 메일)
1. resend.com에서 가입합니다.
2. **회사 도메인을 등록하고 인증**합니다. (도메인 관리자가 DNS에 레코드 몇 개를 추가해야 합니다.) 인증하지 않으면 알림 메일이 스팸함에 들어가고, 가입한 이메일 외에는 발송되지 않습니다.
3. **API 키**를 만듭니다. 보내는 주소는 `알림@회사도메인`처럼 정합니다.

### 3-6. GitHub (소스 코드)
1. github.com에서 **회사 계정(또는 조직)** 을 만듭니다. (소스 코드를 받고, 회사 소유로 보관하는 계정입니다.)
2. 개발 담당자에게 **회사 GitHub 아이디**를 알려 주세요. 개발 담당자가 코드 저장소(`IGSC-chatbot`, 비공개)에 **읽기 권한 초대**를 보냅니다. 초대는 GitHub 알림·이메일로 오며, 받은 뒤 **수락**해야 코드를 볼 수 있습니다(초대는 약 7일 유효).
3. 코드를 내려받은 뒤 회사 계정에 **비어 있는 비공개(Private) 저장소**를 만들어 올리면(4-6) 코드가 **회사 소유**로 독립됩니다. 저장소에는 **비밀번호·키 파일이 올라가 있지 않습니다**(개발 담당자가 제외 설정과 점검을 마쳤습니다).

### 3-7. 도메인과 DNS
- 챗봇 주소를 정합니다(예: `chat.회사도메인`). 홈페이지에 챗봇을 넣는 코드에 이 주소가 들어갑니다. **한 번 정하면 바꾸기 번거로우니**, 챗봇을 홈페이지에 넣기 전에 정하세요.
- 도메인 관리 화면(또는 담당 업체)에서 DNS 레코드를 추가할 수 있는 사람을 인수일에 대기시키세요.

## 4. 내 컴퓨터에 설치하기

Windows 기준입니다. 설치할 때 모르는 선택지가 나오면 **기본값**으로 두고 '다음'을 누르면 됩니다.

### 4-1. Node.js
1. nodejs.org에서 **LTS** 버전을 내려받아 설치합니다. (버전 20 이상)
2. 설치 후 **PowerShell**(시작 메뉴에서 검색)을 열고 확인합니다.
```
node --version
npm --version
```
숫자(예: v22.x.x)가 나오면 성공입니다.

### 4-2. Git
1. git-scm.com에서 Windows용 Git을 설치합니다. (소스를 내려받으려면 필요하고, Claude Code도 Git이 있으면 더 다양한 명령 도구를 쓸 수 있어 권장합니다.)
2. 확인: `git --version`
3. 처음 한 번 이름과 이메일을 등록합니다.
```
git config --global user.name "내 이름"
git config --global user.email "내 회사 이메일"
```

### 4-3. Claude Code
Claude Code는 **말로 시키면 코드를 읽고 고치고 명령을 실행해 주는 도구**입니다. 시스템 운영에서 가장 중요한 도구입니다.
1. **계정**이 필요합니다. **Pro, Max, Team, Enterprise 요금제의 Claude 계정** 또는 **Claude Console 계정**이어야 하며, 무료 claude.ai 플랜에는 Claude Code가 포함되지 않습니다.
2. **설치 (Windows 10 이상)**: **PowerShell**을 열고(관리자 권한은 필요 없습니다) 아래 한 줄을 붙여 넣습니다.
```
irm https://claude.ai/install.ps1 | iex
```
   - 다른 방법: 명령 프롬프트(CMD)용 설치 명령, 또는 `winget install Anthropic.ClaudeCode`
   - **Node.js 없이도 설치됩니다.** (npm으로 설치할 때만 Node.js 22 이상이 필요합니다.)
   - 화면으로 쓰고 싶으면 **Claude 데스크톱 앱**(Windows용)에서도 Code 기능을 쓸 수 있습니다.
   - 설치되면 **새 PowerShell 창**을 열어 확인합니다.
3. 확인: `claude --version` (버전 번호가 나오면 성공). 문제가 있으면 `claude doctor`로 점검합니다.
4. 처음 `claude`를 실행하면 브라우저 로그인 창이 열립니다. 회사 계정으로 로그인하세요. 일반 설치는 **자동으로 업데이트**됩니다(winget 설치는 직접 업데이트).

### 4-4. Vercel CLI
서버에 배포할 때 쓰는 프로그램입니다.
```
npm install -g vercel
vercel --version
```

### 4-5. (선택) VS Code
코드를 눈으로 볼 때 편합니다. code.visualstudio.com에서 설치합니다. 필수는 아닙니다.

### 4-6. 소스 코드 내려받기
개발 담당자의 코드 저장소에서 **직접 내려받는(clone)** 방식입니다. 개발 담당자가 USB나 압축 파일로 폴더를 주지 않습니다.

**① 초대 수락**
1. 메일 또는 GitHub 알림에서 **저장소 초대**(`jonghunkim84-design/IGSC-chatbot`)를 열고 **Accept invitation**(수락)을 누릅니다.
2. 수락 후 https://github.com/jonghunkim84-design/IGSC-chatbot 이 열리면 성공입니다. (초대받은 계정으로 로그인한 상태여야 합니다. 안 열리면 계정이 다른 것입니다.)

**② 내 컴퓨터로 내려받기**
```
cd C:\Users\내이름\Documents
git clone https://github.com/jonghunkim84-design/IGSC-chatbot.git igsc-chatbot
cd igsc-chatbot
npm install
```
- 처음 `git clone`을 하면 **GitHub 로그인 창**이 열립니다. 초대받은 회사 GitHub 계정으로 로그인하세요(Git이 설치될 때 함께 들어오는 인증 도구가 처리합니다). 로그인 창이 안 뜨고 비밀번호를 물으면, GitHub는 비밀번호를 받지 않으므로 **개인 액세스 토큰**(GitHub 설정 → Developer settings → Personal access tokens, 해당 저장소의 읽기 권한)을 비밀번호 대신 입력하거나 `gh auth login`(GitHub CLI)을 쓰세요.
- `npm install`은 시간이 걸릴 수 있습니다(몇 분). 끝나면 폴더 안에 `node_modules`가 생깁니다.
- 폴더 안에 `.git`이 있고 `git log`에 기록이 보이면 변경 이력까지 잘 받은 것입니다.

**③ 회사 저장소로 옮기기 (코드를 회사 소유로)** — 개발 담당자의 저장소에 계속 의존하지 않도록, 회사 GitHub에 **비어 있는 비공개 저장소**(예: `igsc-chatbot`)를 만든 뒤:
```
git remote rename origin source
git remote add origin https://github.com/회사계정/회사저장소이름.git
git push -u origin main
```
- `git log`의 전체 변경 이력이 회사 저장소로 그대로 올라갑니다. 올라간 뒤에는 개발 담당자에게 **"회사 저장소에 올렸다"** 고 알려 주세요. 개발 담당자가 그쪽 초대를 정리합니다.
- 이후 코드 변경은 회사 저장소(`origin`)에 올리세요. (Claude Code에게 "커밋하고 push해 줘"라고 하면 됩니다.)
- 회사 저장소는 **공개(Public)로 바꾸지 마세요.** 문서에 연락처와 운영 정보가 들어 있습니다.

### 4-7. 설치 확인표

| 확인 | 명령 | 정상 결과 |
|---|---|---|
| Node.js | `node --version` | v20 이상 |
| Git | `git --version` | 버전 번호 |
| Claude Code | `claude --version` | 버전 번호 |
| Vercel | `vercel --version` | 버전 번호 |
| 프로젝트 | 폴더에서 `npx tsc --noEmit` | 오류 없이 끝남 |

## 5. Claude Code로 시스템 운영하기

### 5-1. 시작하는 방법
1. PowerShell에서 프로젝트 폴더로 이동합니다: `cd C:\Users\내이름\Documents\igsc-chatbot`
2. `claude`를 입력해 실행합니다.
3. 한국어로 편하게 요청하면 됩니다. Claude Code는 폴더 안의 `CLAUDE.md`(이 시스템의 규칙)와 `docs/` 문서를 읽고 일합니다.

### 5-2. 이런 일을 시킬 수 있습니다

| 하고 싶은 일 | 이렇게 말해 보세요 |
|---|---|
| 시스템 파악 | "이 프로젝트가 어떤 시스템인지 쉽게 설명해 줘" |
| 배포 | "운영 환경에 배포해 줘" |
| 품질 점검 | "대표 질문 회귀 테스트를 돌려서 결과를 알려 줘" |
| 상태 확인 | "운영 상태를 점검해 줘 (DB, AI, 최근 오류)" |
| 백업 | "전체 데이터 백업을 받아 줘" |
| 문구 수정 | "챗봇의 담당자 연락처 안내 문구를 ○○로 바꿔 줘" |

### 5-3. 꼭 지켜 주세요 (안전 수칙)
1. **되돌리기 어려운 작업 전에는 백업부터.** 삭제, 승인 초기화, 키 교체 전에는 "먼저 백업을 받아 줘"라고 말하세요.
2. **FAQ 승인은 사람이 합니다.** 승인은 관리자 화면에서 사람이 직접 누릅니다. Claude Code에게 "FAQ를 전부 승인해 줘"라고 시키지 마세요. 이 시스템의 가장 중요한 원칙입니다(승인된 FAQ만 고객에게 나갑니다).
3. **운영 데이터를 바꾸는 작업은 내용을 확인하고 허락하세요.** Claude Code가 "이 명령을 실행해도 될까요?"라고 물으면, 무엇을 바꾸는지 읽고 답하세요. 모르면 "무슨 일이 일어나는지 설명해 줘"라고 먼저 물으세요.
4. **키와 비밀번호를 대화창에 붙여 넣지 마세요.** 키는 서버의 환경 변수 화면이나 `.env.local` 파일에만 둡니다. (대화 내용이 기록될 수 있습니다.)
5. **`.env.local` 파일을 메일·메신저로 보내지 마세요.** 이 파일에는 운영 데이터를 수정할 수 있는 키가 들어 있습니다.
6. **배포 후에는 꼭 확인하세요.** "배포 후 점검을 해 줘"라고 말하면 헬스체크와 기본 시나리오를 확인해 줍니다.

### 5-4. 비용
- Claude Code 사용 자체의 요금(구독 또는 API 사용량)과, 챗봇이 쓰는 AI 비용(Anthropic 크레딧)은 **별개**입니다. 테스트를 많이 돌리면 챗봇용 크레딧이 줄어듭니다.

## 6. 인수하는 날 해야 할 일

개발 담당자와 **같은 자리에서** 진행하세요(화상 공유도 가능). 계정 비밀번호를 개발 담당자에게 알려 주지 마세요. 로그인이 필요한 순간에는 **담당자 본인이 직접 로그인**합니다.

### 6-1. 시작 전 확인

- [ ] 2장의 계정이 모두 만들어져 있다 (Vercel Pro, Supabase 조직 Pro, Anthropic 크레딧, Resend, GitHub)
- [ ] 챗봇 주소와 도메인 담당자가 정해졌다
- [ ] 관리자로 쓸 이메일 3개가 정해졌다
- [ ] 4장 설치가 끝났다 (설치 확인표 통과)
- [ ] 개발 담당자가 Supabase 조직에 초대돼 있다 (관리자 또는 소유자, 조직 전체 역할)
- [ ] 회사 GitHub 계정이 개발 담당자의 코드 저장소(`IGSC-chatbot`) **읽기 초대를 수락**했다

### 6-2. 진행 순서

| 단계 | 하는 일 | 누가 |
|---|---|---|
| 1 | 개발 담당자가 현재 데이터를 **백업** (FAQ, 대화 기록, 문서 파일) | 개발 |
| 2 | Supabase 프로젝트를 **회사 조직으로 이전** | 개발 (담당자 입회) |
| 3 | 소스 코드를 **개발 담당자의 GitHub 저장소에서 내려받기**(`git clone`) → **회사 GitHub 저장소를 만들어 올리기**(4-6) | 담당자 (개발이 안내) |
| 4 | Vercel에 **회사 계정으로 로그인**하고 새 프로젝트로 배포. 환경 변수(키)를 입력 | **담당자가 로그인**, 개발이 안내 |
| 5 | **도메인 연결**과 로그인 링크 주소 설정 | 담당자(DNS 담당자) + 개발 |
| 6 | **Resend 도메인 인증**과 알림 메일 시험 | 담당자 + 개발 |
| 7 | **정상 동작 점검** (6-3) | 함께 |
| 8 | 키 **재발급**(개발 중 쓰던 키 폐기)과 서버 환경 변수 교체, 재배포 | 개발 → 담당자 확인 |
| 9 | 개발 담당자의 **권한 회수** | 담당자 |
| 10 | **인수 확인서**에 서명 (6-4) | 양쪽 |

> 키 재발급(8단계)은 **새 서버가 정상 동작하는 것을 확인한 뒤에** 합니다. 먼저 바꾸면 문제가 생겼을 때 되돌릴 방법이 줄어듭니다.

### 6-3. 정상 동작 점검표

- [ ] 챗봇 주소를 열면 화면이 뜬다
- [ ] 관리자 로그인 메일이 오고, 링크를 누르면 로그인된다 (관리자 3명 모두)
- [ ] FAQ 목록, 미답변 질문, 대화 로그, 문서 보관함, 인증 종류, 운영 상태 화면이 열린다
- [ ] 운영 상태가 **정상**(또는 승인 FAQ 0건에 대한 '주의')이다
- [ ] 문서 보관함에서 파일 1개를 내려받을 수 있다 (저장소 이전 확인)
- [ ] FAQ를 초안으로 하나 만들고 승인하면 챗봇이 그 답을 한다 (확인 후 초안으로 되돌림)
- [ ] 컨설팅 질문("어떻게 하면 통과하나요?")에 정중히 거절한다
- [ ] 알림 메일 시험을 보내면 수신함(또는 스팸함)에 도착한다
- [ ] Claude Code에서 "배포 후 점검을 해 줘"를 실행하면 오류 없이 끝난다
- [ ] 대표 질문 점검(`npm run golden -- --safety`)을 통과한다
- [ ] 홈페이지 삽입 코드의 주소가 새 챗봇 주소로 바뀌었다
- [ ] 관리자 화면 **유입 채널**이 열리고, 채널별 링크가 **새 챗봇 주소 기준**으로 보인다
- [ ] 채널 링크(예: 인스타그램 링크)를 새 창에 열어 시험 질문을 하면 **유입 채널 표의 질문 수가 늘어난다** (9-5)
- [ ] 승인된 FAQ가 하나도 없으면 챗봇이 **"AI 답변 준비 중입니다."** 를 보여 준다 (FAQ가 있으면 정상 답변)

## 9. 챗봇 링크를 채널에 연결하기

챗봇을 **네이버 블로그, 링크드인, 인스타그램, 직원 이메일 서명, 홈페이지**에 연결하고, 어느 채널에서 질문이 얼마나 들어오는지 보는 방법입니다. 홍보·마케팅 담당자도 따라 할 수 있게 **한 단계씩** 설명합니다.

> **이 장을 읽기 전에** — 챗봇 주소는 지금 임시 주소(`igsc-chatbot.vercel.app`)입니다. **정식 도메인이 정해진 뒤에 링크를 거는 것**이 좋습니다. 이미 건 링크는 주소가 바뀌면 모두 새로 갈아 끼워야 합니다(9-7).

### 9-1. 먼저 이해할 것: 링크에 "이름표"를 붙입니다

- 챗봇은 하나입니다. 하지만 **채널마다 이름표가 붙은 링크**를 걸어 두면, 고객이 어느 채널에서 왔는지 알 수 있습니다.
- 이름표는 링크 끝의 `?src=채널이름` 입니다. 예) 인스타그램용 링크는 `https://챗봇주소/chat?src=instagram`
- 고객이 보는 챗봇 화면은 **모든 채널이 똑같습니다.** 이름표는 집계에만 쓰이고 답변에는 영향이 없습니다.
- 한 번 걸어 두면 이후는 자동입니다. 관리자 화면 **유입 채널**에 채널별 질문 수가 쌓입니다.

| 채널 | 링크의 이름표 | 링크 모양 (예) |
|---|---|---|
| 홈페이지 | `src=homepage` | `https://챗봇주소/chat?src=homepage` (챗봇 버튼은 자동) |
| 네이버 블로그 | `src=naver-blog` | `https://챗봇주소/chat?src=naver-blog` |
| 링크드인 | `src=linkedin` | `https://챗봇주소/chat?src=linkedin` |
| 인스타그램 | `src=instagram` | `https://챗봇주소/chat?src=instagram` |
| 직원 이메일 서명 | `src=email-signature` | `https://챗봇주소/chat?src=email-signature&c=직원이름` |

### 9-2. 링크 복사하는 방법 (직접 쓰지 말고 반드시 복사하세요)

1. 관리자 화면에 로그인합니다.
2. 위쪽 메뉴 **유입 채널**을 엽니다.
3. 화면 아래쪽 **채널별 링크 만들기**로 내려갑니다. 채널마다 링크가 한 줄씩 있습니다.
4. (선택) **캠페인 이름** 칸에 이름을 쓰면 모든 링크 뒤에 `&c=이름`이 붙습니다. 이름 짓는 규칙은 9-4를 보세요. 처음에는 비워 두어도 됩니다.
5. 걸려는 채널 줄 오른쪽의 **복사** 버튼을 누릅니다. 버튼이 **"복사됨"** 으로 바뀌면 복사된 것입니다.
6. 아래 9-3에서 그 채널에 해당하는 곳에 붙여 넣습니다.

> **꼭 지킬 것 두 가지**
> 1. 링크를 **손으로 고쳐 쓰지 마세요.** 한 글자만 틀려도 "기타" 또는 "알 수 없음"으로 집계됩니다. 항상 복사해서 쓰세요.
> 2. **링크 단축 서비스**(줄임 주소)를 쓰려면, `?src=…` 가 **붙은 완성된 링크**를 단축하세요. 단축 서비스가 뒤의 주소를 지우면 "직접 입력·알 수 없음"으로 들어갑니다.

### 9-3. 채널별 연결 방법

> **화면 이름에 대하여** — 각 서비스는 화면 이름과 위치를 바꿀 수 있습니다. 아래는 일반적인 순서이고, 이름이 조금 달라도 같은 메뉴를 찾으시면 됩니다. 공식 문서로 단계를 확인한 서비스는 **Gmail, Outlook** 이고, 나머지(인스타그램, 링크드인, 네이버 블로그, 네이버 메일)는 일반적인 방법이라 실제 화면에서 한 번 더 확인이 필요합니다.

#### ① 홈페이지

| | 방법 A. 챗봇 버튼(권장) | 방법 B. 홈페이지 안의 글·배너에 링크 |
|---|---|---|
| 무엇 | 홈페이지 **오른쪽 아래 둥근 버튼** | 메뉴, 배너, 게시물 속 "챗봇으로 문의하기" 글자나 버튼 |
| 어떻게 | 삽입 코드 **한 줄**을 모든 페이지에 넣습니다. 홈페이지 담당 업체에 `docs/widget-install.md`를 전달하세요. | 위 9-2에서 **홈페이지** 링크를 복사해 해당 글자·버튼의 링크 주소로 넣습니다. |
| 채널 표시 | **자동으로 "홈페이지"** 로 기록됩니다(따로 할 일 없음). | `src=homepage` 가 붙은 링크이므로 같은 "홈페이지"로 합쳐 집계됩니다. |

삽입 코드(새 챗봇 주소로 바꿔서 전달):
```
<script src="https://챗봇주소/widget.js" async></script>
```
- 위치를 나눠 보고 싶으면 방법 B 링크에 캠페인 이름을 붙이세요. 예) `top-banner`(상단 배너), `footer`(하단).
- 연결한 뒤 **9-5의 확인**을 꼭 하세요.

#### ② 네이버 블로그

**어디에 거나요?** ⓐ 글 본문 끝의 안내 문구 ⓑ 블로그 소개글(프로필 영역) ⓒ 고정(공지) 글

1. 9-2에서 **네이버 블로그** 링크를 복사합니다.
2. 블로그 **글쓰기** 화면에서 안내 문구를 씁니다. 예) `인증 절차·비용·기간이 궁금하신가요? IGSC 챗봇에게 바로 물어보세요 →`
3. 문구를 선택하고 도구 모음의 **링크(🔗) 버튼**(또는 Ctrl+K)을 눌러 주소를 **붙여 넣고 확인**을 누릅니다.
4. 글을 **발행**한 뒤, **발행된 글에서 링크를 직접 눌러** 챗봇이 열리는지 확인합니다. 스마트폰에서도 눌러 보세요.
5. 블로그 소개글이나 공지 글에도 같은 링크를 걸어 두면 오래된 글에서도 들어옵니다.

- 글마다 구분하고 싶으면 캠페인 이름을 씁니다. 예) `blog-1010` (10월 10일 글).
- 네이버가 링크를 **미리보기 카드**로 바꿔 보여 줘도 주소는 같습니다. 카드를 눌러서 열리는지 확인하세요.

#### ③ 링크드인

**어디에 거나요?** ⓐ 프로필의 **연락처 정보**(웹사이트) ⓑ 게시물 본문 ⓒ 소개글

1. 9-2에서 **링크드인** 링크를 복사합니다.
2. **프로필**로 가서 **연락처 정보(Contact info)** 옆 연필 아이콘을 누릅니다.
3. **웹사이트 추가**를 눌러 링크를 붙여 넣고 종류를 고른 뒤 **저장**합니다. (웹사이트는 여러 개 넣을 수 있는 것으로 알려져 있습니다.)
4. 게시물에 연결하려면 글 본문에 링크를 붙여 넣고 게시합니다. 게시한 뒤 링크를 눌러 확인하세요.

- **직원 개인 프로필**마다 따로 보고 싶으면 캠페인 이름에 직원 이름을 씁니다. 예) `kim`, `lee`.
- 회사 페이지에 거는 경우는 **회사 페이지 관리자 권한**이 필요합니다.

#### ④ 인스타그램

**어디에 거나요?** ⓐ **프로필의 링크**(가장 확실한 위치) ⓑ **스토리의 링크 스티커** ⓒ 게시물·릴스에서는 "프로필 링크를 눌러 주세요"라고 안내

> 게시물·릴스의 **설명(캡션) 안의 링크는 눌러지지 않는 것이 일반적**입니다. 그래서 프로필 링크로 유도하는 방식을 씁니다. 스토리 링크 스티커는 **계정 조건에 따라 제공 여부가 다릅니다.**

1. 9-2에서 **인스타그램** 링크를 복사합니다. 프로필용은 캠페인 이름을 `bio`, 스토리용은 `story-1010` 처럼 붙이면 구분됩니다.
2. 인스타그램 앱에서 **프로필 → 프로필 편집**을 누르고 **링크(외부 링크 추가)** 를 찾아 붙여 넣고 저장합니다.
3. 게시물 설명 끝에 `프로필 링크에서 IGSC 인증 문의 챗봇을 만나보세요`처럼 안내 문구를 씁니다.
4. 프로필로 가서 링크를 눌러 챗봇이 열리는지 확인합니다. 인스타그램 안의 브라우저에서도 열리는지 보세요.

#### ⑤ 직원 이메일 서명

직원이 보내는 모든 메일 끝에 챗봇 링크가 붙는 방식입니다. **직원마다 캠페인 이름을 다르게** 쓰면 누구의 메일에서 문의가 많이 들어오는지도 볼 수 있습니다.

1. 9-2의 **캠페인 이름** 칸에 직원의 영문 이름(예: `kim`)을 쓰고, **직원 이메일 서명** 줄의 링크를 복사합니다.
2. 아래에서 직원이 쓰는 메일 서비스의 순서대로 서명에 붙여 넣습니다. 긴 주소가 보이지 않도록 **"인증 문의 챗봇"** 같은 글자에 링크를 거는 것이 깔끔합니다.

**Gmail** (공식 문서 기준)

1. 오른쪽 위 **설정(톱니바퀴)** → **모든 설정 보기(See all settings)**
2. **일반(General)** 탭을 아래로 내려 **서명(Signature)** 칸을 찾습니다.
3. **새로 만들기**를 누르고 서명을 씁니다. (서명은 최대 10,000자입니다.)
4. 링크를 걸 글자를 선택하고 **링크 삽입 아이콘**을 눌러 주소를 붙여 넣습니다.
5. 페이지 맨 아래 **변경사항 저장(Save Changes)** 을 누릅니다.

**Outlook (새 Outlook / 웹)** (공식 문서 기준)

1. **설정(톱니바퀴)** → **계정(Accounts)** → **서명(Signatures)**
2. **서명 추가(Add signature)** → 이름을 정하고 서명을 씁니다.
3. 링크를 걸 글자를 선택해 링크를 넣고, 새 메일·답장에 자동 적용할지 체크합니다.
4. **저장(Save)**

**Outlook (기존 Windows 버전)** (공식 문서 기준)

1. 새 메일 창에서 **메시지(Message) → 서명(Signature) → 서명(Signatures)**
2. 메일 계정을 고르고 **새로 만들기(New)** → 이름 입력
3. 서명 내용을 쓰고 링크를 넣은 뒤, 기본 서명으로 쓸 곳을 정하고 **확인(OK)**

**네이버 메일 등 다른 메일**: 메일 설정에서 **서명** 메뉴를 찾아 같은 방식으로 붙입니다. (메뉴 이름은 서비스마다 다릅니다.)

서명 예시:
```
김OO 팀장 | 국제지속가능인증원(IGSC)
인증 문의는 챗봇에게 바로 물어보세요 → (이 글자에 링크: https://챗봇주소/chat?src=email-signature&c=kim)
```
- 서명을 바꾼 뒤 **자기 자신에게 메일을 보내** 링크가 눌러지는지 확인하세요.
- 회사 메일 관리자 기능으로 **전 직원 서명을 한꺼번에** 설정할 수 있는 메일 서비스도 있습니다(서비스마다 다름). 이 경우에도 직원별 캠페인 이름이 필요 없으면 하나의 링크를 공통으로 써도 됩니다.

### 9-4. 캠페인 이름 짓는 규칙

캠페인 이름은 **같은 채널 안에서 구분**하려고 붙이는 이름표입니다. **꼭 필요하지는 않습니다.** 처음에는 채널 이름만으로 시작하고, 필요해지면 붙이세요.

| 규칙 | 설명 |
|---|---|
| 쓸 수 있는 글자 | **소문자 영어, 숫자, `-`(하이픈), `_`(밑줄)** 만, **40자 이내** |
| 쓸 수 없는 것 | 한글, 대문자, 띄어쓰기, 특수문자 (쓰면 이름표가 버려지고 채널만 집계됩니다) |
| 같은 이름은 합쳐집니다 | 같은 이름을 계속 쓰면 그 이름 아래 질문이 합산됩니다 |

| 상황 | 추천 이름 |
|---|---|
| 인스타그램 프로필 링크 / 스토리 | `bio` / `story-1010` |
| 네이버 블로그 글 (날짜별) | `blog-1010` |
| 링크드인 게시물 | `post-1010` |
| 직원 이메일 서명 | 직원 영문 이름 `kim` |
| 홈페이지 상단 배너 / 하단 | `top-banner` / `footer` |

### 9-5. 연결한 뒤 꼭 확인하기 (3단계)

링크를 걸 때마다 아래를 해 보세요. 5분이면 됩니다.
1. **걸어 둔 링크를 직접 누릅니다.** 가능하면 스마트폰에서도 눌러 보세요. 챗봇 화면이 열려야 합니다.
2. 챗봇에 **`[실습] 테스트`** 라고 질문을 한 번 보냅니다. (질문은 기록에 남으니 시험이라고 표시해 두면 나중에 구분됩니다.)
3. 관리자 화면 **유입 채널**을 **새로고침**합니다. 해당 채널 줄의 **질문 수가 1 늘었으면 성공**입니다. 기간은 **오늘** 또는 **최근 7일**을 선택해서 보세요.
- 시험 질문은 나중에 **미답변 질문**에서 **처리 완료**로 정리하세요.

### 9-6. 숫자 읽는 법과 활용

| 항목 | 뜻 |
|---|---|
| 대화 수 | 질문을 한 방문(브라우저 탭) 수 |
| 질문 수 | 챗봇에 입력된 질문의 수 |
| 비중 | 전체 질문 중 이 채널의 비율 |
| 답변 완료 / 담당자 이관 / 불만 | 처리 결과별 건수 |
| 답변 성공률 | 답변 완료 ÷ (답변 완료 + 담당자 이관) |

**활용 방법 (매주 5분)**
- **질문이 많은 채널**을 보고 그 채널의 게시물·문구에 더 신경을 씁니다.
- **답변 성공률이 낮은 채널**은 그 채널의 고객이 묻는 질문이 FAQ에 없다는 신호입니다. **미답변 질문**을 열어 FAQ로 만들면 성공률이 올라갑니다.
- 챗봇을 **열기만 하고 질문하지 않은 사람은 집계되지 않습니다.** 링크를 누른 사람 수(클릭 수)는 각 채널의 통계(블로그 통계, 링크드인·인스타그램 분석)를 함께 보세요.

### 9-7. 문제가 생겼을 때 / 링크를 바꿔야 할 때

| 이런 일이 생기면 | 이렇게 하세요 |
|---|---|
| 링크로 질문했는데 질문 수가 안 늘어난다 | 새로고침 후 **기간**을 확인하세요(오늘 / 최근 7일). 링크를 **복사해서** 걸었는지, 끝의 `?src=…` 가 잘리지 않았는지 확인하세요. |
| **"직접 입력·알 수 없음"** 이 많다 | 링크가 단축 서비스에서 잘렸거나, 채널 표시가 없는 주소(`/chat` 만)를 걸었을 수 있습니다. 완성된 링크로 다시 거세요. |
| **"기타(…)"** 로 집계된다 | 등록되지 않은 이름표(예: `src=kakao`)입니다. 오타가 아니라면 채널을 새로 등록해야 합니다(아래). |
| 정식 도메인으로 **주소가 바뀌었다** | 이미 건 링크는 옛 주소를 가리킵니다. 관리자 **유입 채널**에서 링크를 **다시 복사**해 각 채널에서 갈아 끼우세요. 옛 주소 링크는 서버가 내려가면 열리지 않습니다. |
| **새 채널**(예: 카카오톡 채널, 유튜브)을 추가하고 싶다 | Claude Code에게 "유입 채널에 ○○(코드: ○○)를 추가해 줘"라고 요청하세요. 개발 담당에게 부탁해도 됩니다. 추가한 뒤 관리자 화면에 자동으로 나옵니다. |
| 옛 대화는 채널이 비어 있다 | 이 기능을 켜기 전(마이그레이션 0012 적용 전)의 대화는 채널을 알 수 없어 집계되지 않습니다. |
